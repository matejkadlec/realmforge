# content/

The single source of truth for all Realmforge game content. Everything derived from it (Java registrations,
models, textures, lang files, data, quests) is generated by `tools/` and must never be edited by hand.

| Directory | Model | One file per | Generates |
| --- | --- | --- | --- |
| `blocks/` | `BlockDef` (`tools/realmforge_tools/schema/block.py`) | block, `<id>.yaml` | registration with its block item (`GeneratedBlocks`; a `kind` other than `simple` through `world/BlockKinds`), blockstate, block and item models, opaque placeholder textures, loot table `data/realmforge/loot_table/blocks/<id>.json` (drops itself), vanilla mining tags (`minecraft:mineable/<tool>`, `minecraft:needs_<tier>_tool`), recipe `data/realmforge/recipe/<id>.json`, lang `block.realmforge.<id>`, QA expectations |
| `items/` | `ItemDef` (`tools/realmforge_tools/schema/item.py`) | item, `<id>.yaml` | registration (with its tooltip lines, from `use` and `flavor`), item model, lang, placeholder texture (in its `color`, else a colour from a hash of its id), the item tag `data/realmforge/tags/item/use/<use>.json` of each `use`, recipe `data/realmforge/recipe/<id>.json`, QA expectations |
| `curves/` | `CurveDef` (`tools/realmforge_tools/schema/curve.py`) | curve, `<id>.yaml` | `data/realmforge/realmforge/curve/<id>.json`, `ResourceKey` constant, lang (optional name), QA expectations |
| `stats/` | `StatDef` (`tools/realmforge_tools/schema/stat.py`) | attribute (a primary or secondary stat), `<id>.yaml` | registration in `GeneratedStats`, its name as the lang key `attribute.realmforge.<id>` (the attribute's description id), QA expectations |
| `stat_rules/` | `StatRuleDef` (`tools/realmforge_tools/schema/stat_rule.py`) | rule for one primary stat, `<id>.yaml` | `data/realmforge/realmforge/stat_rule/<id>.json`, QA expectations (the bonuses at sample stat values) |
| `spell_schools/` | `SpellSchoolDef` (`tools/realmforge_tools/schema/spell_school.py`) | spell school, `<id>.yaml` | `data/realmforge/realmforge/spell_school/<id>.json`, the damage type `data/realmforge/damage_type/<id>.json`, a placeholder icon `assets/realmforge/textures/gui/sprites/school/<id>.png` (8x8), tag entries (`#minecraft:bypasses_cooldown` and `#minecraft:no_knockback`, magic schools also `#minecraft:bypasses_armor`), lang (name, death message), `ResourceKey` constants, QA expectations |
| `dimensions/` | `DimensionRulesDef` (`tools/realmforge_tools/schema/dimension_rules.py`) | rules of one dimension, `<id>.yaml` | `data/realmforge/realmforge/dimension_rules/<id>.json` (server only), QA expectations (the mob level rule's levels near sample player levels, at the realm's floor and at each structure's) |
| `races/` | `RaceDef` (`tools/realmforge_tools/schema/character.py`) | playable race, `<id>.yaml` | `data/realmforge/realmforge/race/<id>.json`, lang (name, description), QA expectations (the bonuses) |
| `classes/` | `ClassDef` (`tools/realmforge_tools/schema/character.py`) | class, `<id>.yaml` | `data/realmforge/realmforge/class/<id>.json`, lang (name, description), QA expectations (resource, rage, starting kit, the bonuses) |
| `texts/` | `TextGroupDef` (`tools/realmforge_tools/schema/text.py`) | group of texts, `<id>.yaml` | lang keys `<id>.realmforge.<name>`, constants in `GeneratedTexts` |
| `worldgen/<registry>/` | vanilla worldgen JSON (`tools/realmforge_tools/schema/worldgen.py` lists the registries) | entry, `<id>.json` | the same file, copied unchanged to `data/realmforge/<registry path>/` |
| `rooms/**/` | a structure template plus a `RoomDef` sidecar (`tools/realmforge_tools/schema/room.py`) | room, `<name>.nbt` + `<name>.yaml` | the template, normalized, at `data/realmforge/structure/rooms/<path>.nbt` (structure `realmforge:rooms/<path>`) |
| `set_pieces/` | a structure template plus a `SetPieceDef` fit rule (`tools/realmforge_tools/schema/set_piece.py`) | set piece, `<id>.nbt` + `<id>.yaml` | the template, normalized, at `data/realmforge/structure/set_pieces/<id>.nbt` (structure `realmforge:set_pieces/<id>`), its variants as `data/realmforge/worldgen/processor_list/set_pieces/<id>.json`, its spots in the dungeon types, QA expectations |
| `dungeons/` | `DungeonTypeDef` (`tools/realmforge_tools/schema/dungeon.py`) | dungeon type, `<id>.yaml` | `data/realmforge/realmforge/dungeon_type/<id>.json` (server only) with its pool's rooms resolved (template, size, role, weight, connectors, set-piece spots) and the set pieces they take, the item tag `data/realmforge/tags/item/dungeon_key.json` of every type's `key`, lang (name), QA expectations |
| `kill_xp_multipliers/` | `KillXpMultiplierDef` (`tools/realmforge_tools/schema/kill_xp_multiplier.py`) | kill XP multiplier of one entity type, `<id>.yaml` | `data/realmforge/realmforge/kill_xp_multiplier/<id>.json` (server only), QA expectations (the multiplier at sample sizes) |
| `chapters/` | `ChapterDef` (`tools/realmforge_tools/schema/chapter.py`) | story chapter, `<id>.yaml` | `data/realmforge/realmforge/chapter/<id>.json`, its advancement `data/realmforge/advancement/chapter/<id>.json`, lang (name), QA expectations (the chapters, the level caps of sample sets of completed chapters, and leveling's XP numbers) |
| `effects/` | `EffectDef` (`tools/realmforge_tools/schema/effect.py`) | status effect, `<id>.yaml` | a `MobEffect` registration in `GeneratedEffects`, a placeholder icon `assets/realmforge/textures/mob_effect/<id>.png`, lang (name, `effect.realmforge.<id>`), QA expectations |
| `spells/` | `SpellDef` (`tools/realmforge_tools/schema/spell.py`) | spell, `<id>.yaml` | `data/realmforge/realmforge/spell/<id>.json`, `ResourceKey` constants (`GeneratedSpells`), lang (name, description), QA expectations |
| `mobs/` | `MobDef` (`tools/realmforge_tools/schema/mob.py`) | custom mob, `<id>.yaml` | an entity type of its archetype in `GeneratedMobs` with its attributes, its loot table `data/realmforge/loot_table/entities/<id>.json` (one pool per drop) and each variant's `entities/<id>/<variant>.json`, its entity type tags `data/realmforge/tags/entity_type/<tag>.json`, placeholder GeckoLib model, animations and textures (`assets/realmforge/geckolib/`, `textures/entity/<id>.png` or one per variant, `<id>_<variant>.png`), lang (name, `entity.realmforge.<id>`), QA expectations |
| `sounds/` | `SoundGroupDef` (`tools/realmforge_tools/schema/sound.py`) | the sound events of one subject, `<id>.yaml` | `assets/realmforge/sounds.json` entries, registrations in `GeneratedSounds`, lang (subtitles, `subtitles.realmforge.<category>.<id>.<name>`) |
| `apotheosis_affixes/` | `ApotheosisAffixDef` (`tools/realmforge_tools/schema/apotheosis_affix.py`) | Apotheosis attribute affix it replaces, `<id>.yaml` (`affix` names it) | `data/apotheosis/apotheosis/affixes/<path>.json`, which replaces Apotheosis's own affix at that path (ADR 0038) |
| `realms/` | `RealmDef` (`tools/realmforge_tools/schema/realm.py`) | realm, `<id>.yaml` | `data/realmforge/realmforge/realm/<id>.json` (synced), its unlock advancement `data/realmforge/advancement/realm/<id>.json`, lang (name, subtitle, description, hint, flavour), QA expectations |

Rules:

- One YAML file per entry; the file name (without `.yaml`) must equal the entry's `id`.
- References to other content use full ids (`minecraft:ingredients`, `realmforge:test_item`); every one is
  validated against the ID universe (`tools/id_universe/`) plus our own content. Lists of ids must not repeat
  an entry (e.g. the same creative tab twice crashes the game).
- Player-facing texts are `LocalizedText` with one locale, `en_us`, which is required: Realmforge is English
  only (Matěj, 2026-10-13), so any other locale key (`cs_cz`, ...) is an error. In lore and texts the in-game
  world is always called **Realmforge**, and every text follows the [lore style guide](../docs/lore/style.md).
- **Community translations** need nothing from the pipeline: a translator ships a resource pack with
  `assets/realmforge/lang/<locale>.json`, keyed by the same translation keys as the generated `en_us.json`. A
  translation contributed to the mod is the same file under `mod/src/main/resources/`, which `rf gen` never
  touches.
- **Labels use Title Case** (Matěj, 2026-10-13), for readability: names (items, stats, spells, mobs, realms),
  key mapping names, setting names, screen, button and tab titles, guide chapter and section names, and short
  status messages: `Dark Vision On`, `Toggle Dark Vision`, `Character Sheet`. Every word starts with a capital
  except articles, conjunctions and prepositions of up to three letters (`a`, `an`, `the`, `and`, `but`, `or`,
  `of`, `in`, `on`, `at`, `to`, `for`, `by`) that are neither the first nor the last word: `Ring of the Deep`,
  `Dark Vision On`. Whole sentences (tooltip explanations, quest, lore and dialog text, a chat line that reads as
  a sentence) stay in sentence case.
- `texts/` holds player-facing texts that belong to no other type (key mapping names, messages). The group id
  is the key prefix (`key`, `message`, ...) and must not be another type's prefix (`item`, `curve`); Java
  names a text through its `GeneratedTexts` constant (`KEY_DARK_VISION`), never by typing the key. A group id may
  contain dots where the game prescribes a key format: `key.category.yaml` names key categories, which Options >
  Controls reads from `key.category.<namespace>.<path>` (constant `KEY_CATEGORY_MAIN`). `item_use.yaml` holds the
  green "Use:" tooltip line of each item use, named after the use; validation requires one for every use an item
  names.
- `items/` may give an item a `use`, what right-clicking it does, one item used up each time
  ([architecture 13](../docs/architecture.md#13-items-gear-and-loot)): `unlearn_stat_points` returns every spent
  stat point (the Scroll of Oblivion, RLM-196). The pipeline puts the item into the tag `realmforge:use/<use>`,
  which the game's code for that use reads. An optional `flavor` is a one-sentence flavor line under it in the tooltip, with no
  mechanics, at most 12 words ([lore style guide](../docs/lore/style.md)). `fire_resistant: true` keeps the dropped
  item from burning in fire and lava, as netherite's (a realm's signet). The signet of a realm in `realms/` gets one
  tooltip line of its own: "Does not consume on use" (`tooltip.yaml`'s `signet_not_consumed`).
- `blocks/` may give a block a `kind`, what it does ([architecture
  6.2](../docs/architecture.md#62-what-each-content-type-becomes)): `simple` (the default, a full block),
  `dungeon_portal` (a dungeon key opens it, lit while open; models `<id>` and `<id>_open`) or `dungeon_exit` (the way
  out of a dungeon, a plate one pixel high without collision; one block at most)
  ([15.5](../docs/architecture.md#155-instances)), or one of the realm portal's three, which come together, one block
  each ([15.1](../docs/architecture.md#151-dimensions)): `realmforge_bricks` (the frame) and `realmforge_sealstone` (the
  frame's bottom middle) have the blockstate property `generated`, which a trip sets on the frames it builds, and drop
  only without it; `realm_portal`, the portal block, has no item, loot table, recipe or creative tab, and its model is a
  pane across either axis, tinted with the destination realm's colour from a greyscale, see-through texture.
- `items/` and `blocks/` may give an entry a `recipe`: a shaped crafting recipe that makes it, its `pattern` (one to
  three rows of one to three characters, all the same width, a space for an empty slot), its `key` (each character
  of the pattern, and only those, to an item id), an optional `count` (1) and recipe book `category` (`misc`). It
  becomes vanilla's `minecraft:crafting_shaped` JSON.
- `mobs/` defines our custom mobs ([architecture 14.2](../docs/architecture.md#142-custom-mobs)). A mob picks an
  `archetype`, `melee` or `caster`. A melee mob's `melee` sets its `attack_interval_seconds` (1 by default, vanilla's)
  and `knock_up_blocks`, how high each hit throws its target; a caster names its `spells` (each one that targets an
  enemy and reaches farther than one kiting step) and its `kiting` (`step_blocks`, `speed_percent` of its walking
  speed: the quick step it takes between casts) under `caster`. `attributes` are its numbers at level 1, which its
  level scales like every hostile mob's; `idle` is `stroll` (wanders) or `guard` (stands at the spot where it first
  stood and walks back to it); `sounds` name sound events, ours from `sounds/` (`realmforge:entity.<mob>.<name>`) or
  vanilla's, and `step: silent` walks without a sound; `death_particles` names the block it breaks apart into when it
  dies (its body gone at once); `tags` puts it in our entity type tags (`realmforge:stone_creatures`, which a
  projectile may spare). Each entry of `loot` drops on its own: an `item`, its `count` (`min` to `max`, 1 by default),
  its `chance_percent` (100 by default), and what each level of Looting adds: `looting_count` more at most (0 to
  that many) and `looting_chance_percent` to the chance. Two or more `variants` (`id`, `weight`, `accent`, `loot`)
  give a mob kinds rolled at spawn, each with its own texture and its own loot table, the mob's drops and its own.
  Trash loot is refused: every drop must be worth having (the vision), so no sticks, nuggets, rotten flesh, dirt or
  cobblestone (`TRASH_LOOT` in `schema/mob.py`). `model` shapes the placeholder until A2's art: a `build`
  (`humanoid`, `slim`, `golem`), a `surface` (`speckled`, `smooth`, `mossy_bricks`), `eyes` (`dot`, `tall`, or `gem`
  in the variants' accents) and its `color` (and `moss`). A mob's id must not be one of `texts/entity.yaml`'s names,
  which name the hand-written entity types with the same keys.
- `sounds/` holds our sound events ([ADR 0007](../docs/decisions/0007-asset-pipeline.md), A3): one file per subject
  (a mob, a spell, a block), its `category` (`entity`, `block`, `item`, `spell`, `ambient`, `ui`) and its `events`,
  each `realmforge:<category>.<subject>.<name>` with a `subtitle` (vanilla's style: "Hewn Sentinel cracks") and the
  vanilla `sounds` it plays, one at random, each with its own `volume` (at most 1) and `pitch` (0.5 to 2). They
  become `assets/realmforge/sounds.json` entries that play vanilla's events by reference (never copies of vanilla's
  files), `GeneratedSounds` registrations and the subtitles `subtitles.realmforge.<...>`. New sounds (RLM-126) later
  replace what an event plays, never its id.
- `dungeons/` names each type's `key`, the item that opens a dungeon portal to it (one type per key), and
  `open_minutes`, how long that portal stays open (1 to 240).
- Human units in YAML, game units in data: a field named `<name>_seconds` is written as `<name>_ticks`, one named
  `<name>_percent` as the fraction `<name>` ([architecture 6.3](../docs/architecture.md#63-conventions)).
- `stats/` defines our attributes ([architecture 8.1](../docs/architecture.md#81-the-attribute-set)). Every stat
  has a `name`, which the character sheet and item tooltips show. A stat counts points (`default`, `max`) or is a
  share (`default_percent`, `max_percent`, shown as a percentage); its minimum is 0, and a primary stat counts
  points. `stat_rules/` says what one primary stat gives, per point (with an optional cap, `max` or `max_percent`
  in the amount's unit) and at milestones
  ([8.3](../docs/architecture.md#83-derived-stats-and-milestones)). A rule reads a primary stat no other rule reads
  and writes only secondary stats and vanilla attributes (`minecraft:attack_damage`). An `add_value` amount on one
  of our stats takes its unit (`amount_percent` for a share, `amount` for points); on a vanilla attribute, whichever
  fits it (`minecraft:knockback_resistance` is a fraction, so `amount_percent: 5` adds 5 %). Multiplied operations
  always take `amount_percent`.
- `spell_schools/` defines the kinds of damage ([architecture 9.1](../docs/architecture.md#91-damage-pipeline)):
  `physical` (armor reduces it, it can be dodged) or `magic` (bypasses armor; spell power raises it). `power` and
  `resistance` name secondary stats that are shares (`fire_power`, `fire_resistance`), each serving one school.
  The death message names only the victim, `%1$s`: the game passes the killer only sometimes. `color` is the
  colour of the school's spells (spell bar frames, the cast bar, damage numbers in tooltips); `combat_text_color`
  (the `color` when left out) is the floating combat text's colour of the school's hits. The Physical school's combat
  text colour is every hit's that is not magic (melee and ranged too), red on a crit.
- `dimensions/` holds the gameplay rules of a dimension, which `dimension` names (`minecraft:overworld`, or one of
  ours from `worldgen/dimension/`); at most one entry per dimension
  ([architecture 14.1](../docs/architecture.md#141-mob-levels)). Its optional `mob_levels` rule gives every hostile
  mob spawning there a level near the nearest player's: `weights` holds the weight of each offset from the player's
  level, an odd number of them (1 to 1000 each, at most 10 either side), the middle one for the player's own level
  (`[5, 10, 20, 30, 20, 10, 5]` is −3 to +3); no mob that spawns there is below `entry_level`, the realm's floor (the
  level needed to enter it), nor above `max_level`. The floor and the cap drop offsets and the rest share the chance
  by their weights; a player below the floor meets every mob at it. Its optional `structure_floors` raise the floor
  of the mobs a structure holds (RLM-342): `{structure: <id>, level: <n>}`, the structure a world generation
  structure (`minecraft:ancient_city`) or a structure tag after `#` (`'#minecraft:village'`, quoted in YAML), the
  level above `entry_level` and at most `max_level`, one entry per structure or tag. A mob that gets its level inside
  one of the structure's pieces is never below that level, and inside several, never below the highest; the
  Overworld's Ancient Cities are 40 and more. A mob keeps the level it spawned with. What a level adds
  comes from the curves
  `mob_health` (a multiple of maximum health), `mob_damage` (a multiple of the damage of every hit the mob causes)
  and `mob_armor` (armor points). Its optional `access` lists what a player needs to enter the dimension, every one
  at once, refused on every way in (a portal, `/tp`, a warp; [architecture 15.1](../docs/architecture.md#151-dimensions)):
  `{type: realmforge:has_advancement, advancement: <id>}` (an advancement that exists, ours or vanilla's),
  `{type: realmforge:level_at_least, level: <n>}` or `{type: realmforge:chapter_completed, chapter: <chapter>}`.
- `blocks/` holds simple full blocks that drop themselves: `hardness` (stone 1.5, obsidian 50; `-1` for a block nothing
  breaks, which then has no `tool`), `blast_resistance` (6 by default), the `tool` that mines it at full speed,
  `requires_tool` (drops nothing without that tool, as stone needs a pickaxe; needs a `tool`) with an optional
  `tool_tier` (`stone`, `iron`, `diamond`), its `sound` and `map_color` (vanilla's constants, lower case) and
  `creative_tabs`. Its block item takes its id, so no item in `items/` may share it. Undervault's four stones are the
  first (RLM-32).
- `realms/` holds the realms ([realm portal spec](../docs/design/realm-portal.md)): the realm's `dimension` (one of ours
  from `worldgen/dimension/`, one realm per dimension), its `name` without an article, its `subtitle` (the element), its
  `description` in running text (lowercase, without an article: `stone realm`, which the refusal at the sealstone reads
  as "a portal to the stone realm"), the `locked_hint` a refused player reads (one sentence naming the unlock quest), its
  `levels: [lowest, highest]` (the band the arrival title shows; the lowest is its dimension rules' `entry_level`, the
  highest at most their `max_level`), a `flavour` line and the `icon` item of its unlock. The unlock is the advancement `realmforge:realm/<id>` (criterion
  `minecraft:impossible`: only the realm's quest or a command grants it), which the dimension's rules in `dimensions/`
  must name in their `access`. The realm's dimension type must link by a `coordinate_scale` above 1 and have a
  `minecraft:gameplay/bed_rule` that sets no spawn and does not explode. The portal's fields (W2b): the `signet` that
  opens the realm portal onto the realm (an item of ours that stacks to 1, the signet of no other realm), the portal's
  `colour` (`#RRGGBB`), the `particle` it shows next to the dust in that colour (a vanilla particle without options from
  the list in `schema/realm.py`), the `sound_pitch` of the vanilla portal sounds (0.5 to 2, 1 by default) and the
  `arrival`: the heights `y: [lowest, highest]` a built frame's bottom row may lie at (it replaces the top of the floor,
  so the opening is at floor level; inside the dimension, with its top row in), the `floor` block of a frame carved out
  where nothing fits, and its `pocket_radius` (3). `overworld.yaml` is Overworld's entry
  (`dimension: minecraft:overworld`), which is no realm: only its `name`, `colour` (the return portals') and `arrival`
  (where a way back builds a portal), and no unlock.
- `races/` and `classes/` define who a player can be ([architecture 10.1](../docs/architecture.md#101-races-and-classes)).
  A race lists the classes it may take (each must exist, and every class must be open to some race) and gives
  `modifiers`; a class names its `resource` (`realmforge:mana` or `realmforge:rage`), and a rage class, and only a
  rage class, sets its `rage` numbers: `per_hit_dealt` (rage for a full-strength melee hit dealt, a weaker swing
  giving its share, and a swing giving it once however many mobs it hits), `per_max_health_taken` (rage for losing
  the whole max health to attackers, a hit for a tenth of it giving a tenth), `decay_per_second` and
  `decay_after_seconds` (how long after the last hit dealt or taken the pool starts to decay;
  [architecture 11.5](../docs/architecture.md#115-resources-cooldowns-modifiers)). A class
  gives `modifiers` and a `starting_kit` (items with a `count` of 1 to 64, given once when the character is created; every class's kit
  holds Bread ×32, Matěj, 2026-10-14, which validation checks). A modifier is the stat rules' shape (`attribute`,
  `operation`, `amount` or `amount_percent`, in the same units) and gives the same at every level: levels give stat
  points to spend instead (Matěj, 2026-10-15, RLM-196), so `per_level` is refused. A race's or class's `name` is a
  label (Title Case); its `description` is one or two sentences in the lore style guide's voice, which never assume
  the player's race or class.
- `chapters/` holds the story's chapters, which set the level cap
  ([architecture 10.2](../docs/architecture.md#102-leveling)). A chapter has a `name` (a label), an `order` (1, 2,
  3 without gaps), a `level_cap`, the cap while it is the player's current chapter (the first chapter's is a new
  player's cap), and a `completed_level_cap` above it, the cap once the player completes it; each chapter's
  `level_cap` equals the `completed_level_cap` of the one before it, so no level band is skipped (research PR-16).
  A player completes a chapter by earning its advancement `realmforge:chapter/<id>` (generated, granted only by
  the chapter's last quest or a command). A chapter's cap is its last level (Matěj, 2026-10-15): `chapter_1`
  (Overworld) 10 → 18, `chapter_2` (Undervault) 18 → 30; the later chapters' caps are in
  [architecture 10.2](../docs/architecture.md#102-leveling). XP stops at the cap: a player holds at most the XP
  of the cap's level, so completing a chapter raises the cap but brings no level by itself. Leveling also reads
  five curves, which validation requires: `xp_to_next_level` (the XP from a level to the next, at least 1; one
  point per level from the XP model, 1,500 at level 1 and 98,650 at 59), `kill_xp` (a kill's XP by the victim's
  level, `45 + 5 × level`), `kill_xp_below_player` and `kill_xp_above_player` (the share of it a kill gives, by how
  many levels the victim is below or above the player; the curve's `level` is that difference, and neither curve
  goes below 0), and `stat_points_per_level` (the primary stat points reaching a level gives, rounded half up, never
  below 0; level 1 gives none: 1 a level, Matěj, 2026-10-15, RLM-196).
- `kill_xp_multipliers/` gives the mobs of one entity type, named in `entity`, a kill XP `multiplier` (their rank: 1
  is a normal mob, 0 gives nothing, 10 a boss); a hostile mob without an entry gives 1. A slime or magma cube may
  give by size: `by_size` lists `{max_size, multiplier}` in increasing `max_size` order, the first one the mob's
  size does not exceed applies, and larger ones take `multiplier`. At most one entry per entity type
  ([architecture 10.2](../docs/architecture.md#102-leveling)).
- `effects/` holds our status effects ([architecture 11.4](../docs/architecture.md#114-status-effects), C3c): a
  `name`, a `category` (`beneficial`, `harmful` or `neutral`), a particle `color` (`"#RRGGBB"`), `modifiers` (an
  `attribute`, an `operation` and the first level's `amount`, or `amount_percent` for a multiplied operation or one of
  our shares, as for races and classes; one per attribute; each amplifier level multiplies it, as vanilla does) and
  `periodic` damage or healing (`type: damage` or `heal`, a `school`, the `amount` of a tick at the first level, which
  each amplifier level adds again, and `interval_seconds` from 0.25 to 10): at least one of the two. A tick is a hit
  or heal of the school from the caster that applied the effect, raised by its spell power and school power, and it
  never crits. A spell applies one through `realmforge:apply_effect`, for a whole number of its intervals. The
  `test_*` effects are engine tests, not gameplay content.
- `spells/` holds the spells of players, mobs and bosses ([architecture 11](../docs/architecture.md#11-spells-and-status-effects)):
  a `name` and a `description` (what it does in a sentence or two, shown in its tooltip; numbers come from data
  through placeholders, never prose: `{damage}` and `{heal}` read the first damage or heal effect, a projectile's or
  an area's included, `{duration}` the first `apply_effect`'s seconds, `{periodic}`, `{periodic_total}` and
  `{interval}` that effect's ticks when it is one of ours with `periodic`, `{radius}` the first area's radius;
  validation checks that each has its effect, [architecture 11.6](../docs/architecture.md#116-client-side); a damage
  number shows its school's icon and colour, so write "for {damage} damage", never the school's name); the
  `school` whose damage they deal; what they `scales_with`, `spell_power` for a magic school and `attack_damage`
  for a physical one (off-class stats do nothing for a class's abilities, Matěj, 2026-10-15); their `targeting`
  (`{type: realmforge:self}`, or `realmforge:enemy`, `realmforge:ally`, `realmforge:ground_point` or
  `realmforge:direction` with a `range` of at most 128 blocks; an ally spell without a target takes the caster, a
  ground point without one the first block the caster looks at, a direction where it looks; and for `npc_only` spells
  alone, which validation checks, the NPC types `realmforge:current_target` (the mob's attack target),
  `realmforge:random_player` and `realmforge:farthest_player` (among the players in range and sight that it may
  attack, never one in creative or spectator mode), each with a `range`, which go wherever `realmforge:enemy` does); `cast`: `{type: instant}`, `{type: cast_time, duration_seconds}`
  (the effects, the cost and the cooldown come when the cast completes) or `{type: channel, duration_seconds,
  interval_seconds}` (it pays and starts its cooldown when it begins, then runs its effects every interval; the
  duration is a whole number of intervals), the timed ones with `castable_while_moving` (by default the cast slows
  its caster to half its speed; with `true` the caster moves at full speed; moving never cancels a cast, ADR 0039,
  ADR 0047) and `lock_on` (range and line of sight are not checked again before the effects), or instead
  `keep_sight` (losing sight of the target ends the cast at once) and `keep_range_percent` (for that share of the
  cast the target must stay in range or the cast ends at once; past it, range no longer matters), and `sound` (a sound
  event the caster makes when the cast begins); a cast time may `forms_projectile` (its first effect, a projectile
  with an `appearance`, grows in front of the caster during the cast and flies from there); an optional `cost` (`resource` `realmforge:mana` or `realmforge:rage`, `amount` at level 1, `per_level`);
  `cooldown_seconds`; `global_cooldown_seconds` (0.5 by default, as in WoW; 0 for a spell off the global cooldown);
  `max_level`;
  the `crit` block (`can_crit`, `multiplier_percent` instead of 1 + the caster's crit damage, `bonus_chance_percent`
  added to the caster's crit chance; every spell can crit by default, heals too); `npc_only` for mob and boss
  spells; and the `effects`, in order: `realmforge:damage` (a hit of the school on an enemy) and `realmforge:heal`
  (on the caster or an ally), each with `amount` at level 1 and `per_level`, and `attack_damage_percent` (the share
  of the caster's attack damage added) on an attack damage spell, where its damage effects need one;
  `realmforge:apply_effect` (`effect`, a status effect id: one of ours from `effects/`, or a vanilla one such as
  `minecraft:slowness`, never an instant one such as
  `minecraft:instant_health`, which would apply every tick: use `realmforge:heal` or `realmforge:damage`;
  `duration_seconds` up to 60, `amplifier`) and `realmforge:remove_effect` (`effect`) on any entity target; `realmforge:knockback` (`strength`,
  0.4 is a melee hit's) on an enemy, which also interrupts its cast; `realmforge:projectile` (`speed` in blocks per
  second, `size`, `lifetime_seconds`, and its own `effects` on the first enemy it hits; `spares`, an entity type tag
  whose entities stop it untouched; `impact`, a `sound` and a block's break `particles` where it hits; `appearance`,
  `{model: orb, color}`, its look, with a placeholder texture `textures/entity/spell/<spell>.png`, one per spell) at
  an enemy, a ground point or along a direction; `realmforge:area` (`radius`, `duration_seconds`, `interval_seconds`, `affects: enemies` or
  `allies`, and its own `effects` on each of them inside at every interval) at the caster's feet, an enemy's or a
  ground point; `realmforge:teleport` (the caster to a ground point, or along a direction as far as its range and
  blocks allow); and `realmforge:dash` (`strength`, a burst of speed in blocks per tick toward an enemy, a ground
  point or along a direction). The effects of a projectile or an area must fit whom they reach: no heal on a
  projectile, no damage in an area for allies ([architecture 11.3](../docs/architecture.md#113-spell-entities)). A
  `per_level` needs a `max_level` above 1, on the effects of a projectile or an area too. The `test_*` spells are
  engine tests (like `items/test_item`), not gameplay content.
- `worldgen/` is the one exception to YAML: Minecraft's own worldgen JSON (`dimension/`, `dimension_type/`,
  `biome/`, `noise_settings/`, ...), validated (location, id, JSON, dimension types, no clash with the core mod's
  own `realmforge:instances`) and copied byte for byte; the game decodes it when a world loads.
- `rooms/` is the second exception: dungeon rooms are structure templates (`.nbt`), each with a YAML sidecar of
  the same name ([architecture 15.4](../docs/architecture.md#154-rooms),
  [ADR 0028](../docs/decisions/0028-dungeon-rooms-generated-or-imported.md)). A room's id is its path below
  `rooms/` without the suffix (`third_party/stonevaults/hall_a`), in lowercase snake_case folders and names; the
  sidecar names the room `pools` the room joins (a dungeon type is built from one pool), its `tags` (slot types),
  its `weight` (how often the planner picks it among the rooms that fit, 1 to 150), the rules for how dungeons treat
  it when it needs any: `max_per_layout` (the most times one layout holds it, RLM-256), `near_start: true` (it hangs
  only off the entrance or the first room of the main path, RLM-256) and `explosion_breaks` (the blocks an explosion
  inside it may break in an instance, where explosions otherwise break nothing: what a trap's TNT is meant to blow
  open, validated as block ids, RLM-257), and, for an imported room, its `source`. Stonevaults' throne room
  (`treasure/mooshroom_king`) is limited to one per layout at the start, and its combination lock
  (`rooms/combination_lock`) lets its TNT break the smooth stone, gravel and redstone that close its way on.
  `uv run rf rooms import` writes both files ([tools/README](../tools/README.md#rooms)); nobody
  edits a template by hand. Validation checks the size (at most 48 blocks per axis), the template's data version
  (required, no newer than the game's), every block, block entity and entity id and every container's loot table
  against the ID universe, that jigsaws sit on the room's boundary, facing out, and that every jigsaw's pool is a
  vanilla template pool (`minecraft:empty` when it names none) or a room pool some sidecar lists. Imported rooms
  live in `rooms/third_party/<source>/` next to the source's `LICENSE` and `NOTICE` (and, for an LGPL-3.0 source,
  `COPYING`, the GPL-3.0 text), which validation requires and `rf gen` copies to the jar's
  `META-INF/third_party/<source>/`; an imported room elsewhere must be one we built ourselves, marked
  `source.ours: true` (`rf rooms import --ours`). The import rules of each source are in
  [art/rooms/](../art/rooms/README.md). A `review.yaml` in any folder records the room gallery's keep and reject
  decisions for the rooms below it: a kept room must exist, a rejected one may be dropped (the import then skips
  it).
- Room tags name the slots a room fills in a dungeon layout. `rf rooms import` drafts them for a new sidecar
  (`tools/realmforge_tools/rooms/slots.py`), and they are corrected by hand: one **role** (`entrance`, `hallway`,
  `combat`, `treasure`, `boss`, `stairs`), the **shape** its connectors give (`dead_end`, `straight`, `curved`,
  `t_junction`, `crossing`), and `vertical` when it connects up or down. So a straight hallway is
  `[hallway, straight]` and a treasure room at the end of a branch `[treasure, dead_end]`. Connectors of imported
  rooms are named `realmforge:door` on the sides and `realmforge:shaft` up and down. A room in the pool of a dungeon
  type must have exactly one role.
- A room marks spots with **data markers**: structure blocks in data mode whose metadata names `entrance` (where
  players arrive, one at most, only in an entrance room; without one they arrive at a free spot near the room's
  middle), `exit` (W4d), `mob` or `chest` (W6)
  ([architecture 15.3](../docs/architecture.md#153-generation-pure-first-then-minecraft)). The builder reads them
  and never places them, and validation refuses any other structure block. A room in the pool of a dungeon type
  keeps its fluids (water, lava, waterlogged blocks, kelp, seagrass) from reaching its sides and floor, through a
  floor hole or a wall gap too, where they would flow out of its box past what cleanup clears; only its connectors
  may let a fluid through, into the next room, and each only through its own face (not down out of a side
  connector in the floor layer, not sideways out of one on an edge).
- `set_pieces/` is the third exception: small hand-built dressing that the dungeon fits into rooms
  ([architecture 15.4](../docs/architecture.md#154-rooms), [design](../docs/design/set-pieces.md),
  [ADR 0050](../docs/decisions/0050-set-pieces-hand-built-nbt-placed-at-dungeon-generation.md)), each a structure
  template (`.nbt`) with a fit rule of the same name, directly in `set_pieces/` (no folders). The fit rule names the
  `id` (its file name), the `mask`: a top view, one character per cell, cells separated by single spaces, the first row
  the wall side (north) and the room below it (`W` wall, `.` the piece, `_` clearance a player stands on, `?`
  anything); the `height` (1 to 3, the template's too); `builds_walls: true` for a piece whose template holds its `W`
  cells (it then needs a flat wall and free space, not a real niche); the `walls` its `W` cells may be in a generated
  room (theme roles such as `wall`, the walls' base, body, patches and cornice, or `pillar`, or block ids; an imported
  room takes any full block for a role); its `tags` (what it is: storage, prison, crypt, ...; at least one); the room
  `roles` it may appear in (default `[hallway, combat]`); its `weight` (1 to 150); and `variants`: `mirror` (the builder
  may mirror it), `chance` (blocks there only by chance, `minecraft:skeleton_skull: 0.5`) and `swaps` (a block that
  may become another: `to` a block state as the template has it, `chance`, and `keep`, the properties it takes over).
  `source` names the workshop jig's save it came from. The template is built as the mask shows it, wall to the north,
  and holds the piece's cells only (not even air elsewhere), no connector, marker, spawner, redstone, fluid,
  locked-looking door or container loot table. `uv run rf set-pieces import` writes both files from a jig save
  ([tools/README](../tools/README.md#set-pieces)); validation refuses a drafted fit rule until its `tags` are filled
  in. `test_barrel` is test content (like `items/test_item`): it gives the test dungeon's rooms spots.
- `room_specs/` holds the rooms the room generator builds (A4d,
  [architecture 15.4](../docs/architecture.md#154-rooms)): the `kind` (`entrance`; the hallways `corridor` with
  two opposite connectors, `curve` with two adjacent, `t_junction` with three, `crossing` with four and `dead_end`
  with one; `combat`; `treasure`; `arena`, the boss's room), the `theme` (`realmforge:<id>` of `room_themes/`), the
  `footprint` (`[x, z]`, 5 to 16 blocks, walls included), the `height` (5 to 16, floor and ceiling included), the
  `connectors` (the sides with a doorway), the `features` (`pillars`, `alcoves`, `pit`, `balcony`, `rubble`), and
  the `pools` and `weight` of its rooms. A feature that does not fit is refused (a pit needs 9 × 9 and a height of
  6, a balcony a height of 9 and a side without a doorway, alcoves such a side and 7 blocks, pillars 7 blocks).
  `seeds` are the candidates the gallery review kept: each is a room `generated/<spec>/seed_<n>` in the jar, with
  the tags of its kind and connectors. `rejected_seeds` are the ones it rejected. Both are written by
  `rf rooms review` on the candidates folder, as flow lists on one line (`seeds: [2, 7]`); see
  [tools/README](../tools/README.md#rooms). A generated room must let a player walk between its doorways with three
  blocks of headroom and leave no cell dark where a mob could spawn, which validation checks.
- `room_themes/` names, for each neutral role the room generator builds with (`floor`, `floor_variant`,
  `floor_border`, `wall_base`, `wall_body`, `wall_body_cracked`, `wall_body_mossy`, `wall_cornice`, `ceiling`,
  `pillar`, `stairs`, `slab`, `rubble`, `rubble_slab`, `wall_light`, `ceiling_light`), the block it is in this
  theme: a full solid block, a stairs block, a slab, a wall torch or a lantern as the role needs, each role its own
  block, so a theme swap (W4) can tell them apart. `stone_vault` is the one theme so far.
- `dungeons/` holds the kinds of dungeons ([architecture 15.2](../docs/architecture.md#152-dungeon-types)): a
  `name` (a label), the room `pool` the type is built from, and the `layout` the planner follows, each range
  written `[min, max]`: `main_path` (rooms between the entrance and the ending, 1 to 32), `branches` (side branches
  off the main path's rooms, 0 to 16), `branch_rooms` (rooms per branch, its dead end included, 1 to 8) and
  `ending` (`boss` or `treasure`, the role of the room that ends the main path). The planner closes every connector
  left over with a dead end, so a layout holds more rooms than these counts. Validation wants in the pool an
  entrance (role `entrance`, a connector), a room to pass through (role `hallway`, `combat` or `stairs`, two
  connectors; three when `branches` starts above 0), a room with the ending's role, and a dead end (one connector,
  role `hallway`, `combat`, `stairs` or `treasure`), and every connector of its rooms must meet one of the pool by the
  jigsaw rules (its `target` is the other's `name`; sides meet sides, up meets down). `rf gen` resolves the pool into
  the entry, so the game plans without loading a template, and writes each room's set-piece spots into it: the
  patterns where the pieces that reach the room's role fit, each with the pieces that may fill it. `test_dungeon` is test content (like `items/test_item`)
  that only `/qa dungeon plan`, `build` and `enter` use; W6 brings the real dungeon types.
- Start each YAML file with the `yaml-language-server` schema comment (see `items/test_item.yaml`) for editor
  completion.

After editing: `uv run rf gen` (validates, then regenerates). See `CLAUDE.md` for the full workflow.
