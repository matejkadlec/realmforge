# content/

The single source of truth for all Realmforge game content. Everything derived from it (Java registrations,
models, textures, lang files, data, quests) is generated by `tools/` and must never be edited by hand.

| Directory | Model | One file per | Generates |
| --- | --- | --- | --- |
| `items/` | `ItemDef` (`tools/realmforge_tools/schema/item.py`) | item, `<id>.yaml` | registration, item model, lang, placeholder texture |
| `curves/` | `CurveDef` (`tools/realmforge_tools/schema/curve.py`) | curve, `<id>.yaml` | `data/realmforge/realmforge/curve/<id>.json`, `ResourceKey` constant, lang (optional name), QA expectations |
| `stats/` | `StatDef` (`tools/realmforge_tools/schema/stat.py`) | attribute (a primary or secondary stat), `<id>.yaml` | registration in `GeneratedStats` (description id `attribute.realmforge.<id>`), QA expectations; names come with RLM-136 |
| `stat_rules/` | `StatRuleDef` (`tools/realmforge_tools/schema/stat_rule.py`) | rule for one primary stat, `<id>.yaml` | `data/realmforge/realmforge/stat_rule/<id>.json`, QA expectations (the bonuses at sample stat values) |
| `texts/` | `TextGroupDef` (`tools/realmforge_tools/schema/text.py`) | group of texts, `<id>.yaml` | lang keys `<id>.realmforge.<name>`, constants in `GeneratedTexts` |
| `worldgen/<registry>/` | vanilla worldgen JSON (`tools/realmforge_tools/schema/worldgen.py` lists the registries) | entry, `<id>.json` | the same file, copied unchanged to `data/realmforge/<registry path>/` |

Rules:

- One YAML file per entry; the file name (without `.yaml`) must equal the entry's `id`.
- References to other content use full ids (`minecraft:ingredients`, `realmforge:test_item`); every one is
  validated against the ID universe (`tools/id_universe/`) plus our own content. Lists of ids must not repeat
  an entry (e.g. the same creative tab twice crashes the game).
- Player-facing texts are `LocalizedText`: `en_us` is required, `cs_cz` is optional. In lore and texts the
  in-game world is always called **Realmforge**.
- `texts/` holds player-facing texts that belong to no other type (key mapping names, messages). The group id
  is the key prefix (`key`, `message`, ...) and must not be another type's prefix (`item`, `curve`); Java
  names a text through its `GeneratedTexts` constant (`KEY_DARK_VISION`), never by typing the key. A group id may
  contain dots where the game prescribes a key format: `key.category.yaml` names key categories, which Options >
  Controls reads from `key.category.<namespace>.<path>` (constant `KEY_CATEGORY_MAIN`).
- Human units in YAML, game units in data: a field named `<name>_seconds` is written as `<name>_ticks`, one named
  `<name>_percent` as the fraction `<name>` ([architecture 6.3](../docs/architecture.md#63-conventions)).
- `stats/` defines our attributes ([architecture 8.1](../docs/architecture.md#81-the-attribute-set)). A stat
  counts points (`default`, `max`) or is a share (`default_percent`, `max_percent`, shown as a percentage); its
  minimum is 0, and a primary stat counts points. `stat_rules/` says what one primary stat gives, per point (with
  an optional cap, `max` or `max_percent` in the amount's unit) and at milestones
  ([8.3](../docs/architecture.md#83-derived-stats-and-milestones)). A rule reads a primary stat no other rule reads
  and writes only secondary stats and vanilla attributes (`minecraft:attack_damage`). An `add_value` amount on one
  of our stats takes its unit (`amount_percent` for a share, `amount` for points); on a vanilla attribute, whichever
  fits it (`minecraft:knockback_resistance` is a fraction, so `amount_percent: 5` adds 5 %). Multiplied operations
  always take `amount_percent`.
- `worldgen/` is the one exception to YAML: Minecraft's own worldgen JSON (`dimension/`, `dimension_type/`,
  `biome/`, `noise_settings/`, ...), validated (location, id, JSON, dimension types, no clash with the core mod's
  own `realmforge:instances`) and copied byte for byte; the game decodes it when a world loads.
- Start each YAML file with the `yaml-language-server` schema comment (see `items/test_item.yaml`) for editor
  completion.

After editing: `uv run rf gen` (validates, then regenerates). See `CLAUDE.md` for the full workflow.
